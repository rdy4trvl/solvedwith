Check whether an agent actually did what it said

Microsoft and Hugging Face ran 507 business workflows twenty times each and graded the database afterwards. Most failures ended with the agent reporting success.

What they did

Each task ran against an identical clean backend, and a deterministic judge compared the database state afterwards against the required end state rather than reading the agent's own summary. In the worked example a support agent made nine tool calls, read the refund policy correctly and established the customer did not qualify, then closed the ticket as resolved when the required state was on hold, because the carrier exception was still open.

How it went

Across 121,680 trials on 12 models, 79,853 failed the state checks. Of those failures, 67.24% terminated cleanly, changed state and reported no error: the agent said it was done. Wrong field values appeared in 77.61% of failures, unintended extra effects in 43.30%. The strongest model passed 67.16% of tasks on a single attempt but only 47.53% on all twenty.

Our analysis · Nov 24, 2026

Not from the source. Our own assessment of the approach, which may date as the tools change.

Where it falls down

  • Every task is a synthetic reconstruction and the customers are not real. The authors say so themselves.
  • The cost figures are list-rate estimates rather than bills, and the authors call them a comparative index, not an invoice.
  • The authors recommend human approval on changes you cannot cheaply reverse, then note they have not measured whether it helps.

Worth trying next

  • Grade your own agents on the state they leave behind, not on their closing message. That single change is the whole finding.
  • Run the same task twenty times before trusting it. Passing once and passing every time differed by about twenty points even on the best model here.
